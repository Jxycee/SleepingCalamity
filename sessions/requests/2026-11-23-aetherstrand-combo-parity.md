## What is known (all measured 2026-11-23, cloud, software rendering)
Files the user has: `AetherStrand_SculptedHair_URP_Plugin_v3.0.zip` and `..._v3.0.1.zip` (ask the user for them; they are not in the repo). Neon says v3.0.1 fixes what the cloud session found.

1. **v3.0 does not compile.** `AetherStrand_Unity/Editor/AetherStrandAiDiagnostics.cs` is a 0-byte file but `AetherStrandSetupWindow.cs` calls `AetherStrandAiDiagnostics.CollectReport / ExportBundle / FormatMarkdownSummary` (lines ~572-585): CS0103 on every build.
2. **v3.0.1 compiles** (that file is now ~20 KB) and the hair is no longer magenta (the shader got a Built-in-RP fallback SubShader; the shader itself reports supported, 0 errors). Changed files v3.0 to v3.0.1: Editor/AetherStrandAiDiagnostics.cs, AetherStrandMeshGenerator.cs, AetherStrandSetupWindow.cs, Shaders/AetherStrand_Hair.shader, package.json. The Blender addon is identical in both.
3. **Crown still 9.2 cm above Tobin's skull in v3.0.1, same as v3.0.** Unity 1-click apply (`AetherStrandSetupWindow.ApplyProceduralHairToCharacter`, driven by reflection in the harness) makes 376 locks / 47,376 tris, a 29,328-vertex hair mesh skinned to 221 bones (220 `Hair_` bones under `Head`), and a physics component. Hair bounds centre (0, 1.72, 0.01) size (0.23, 0.29, 0.29); Tobin head (verts weighted over 0.5 to the Head bone) centre (0, 1.65, -0.01) size (0.25, 0.25, 0.25). The fringe reaches the brows and hides the eyes.
4. **Why v3.0.1's new auto-seat did not help (partly diagnosed).** New `AutoSeatLocksToHeadMesh` in `AetherStrandMeshGenerator.cs` runs only when `p.autoFitToHeadMesh && p.headLocalOffset == Vector3.zero`. The window's default `_builder.headLocalOffset` is `(0, 0.005, 0.032)` (ProceduralBuilder.cs:55) and `_useExactHeroPreset` defaults true, so the seat is skipped on the default 1-click path. With the offset forced to zero the seat DID run (log: "Generated 376 volumetric locks ...") and the crown height was still exactly 0.092 m. So the seat returns early or computes no shift on Tobin. NOT pinned down: candidates are the skull filter (|x|<0.16, -0.14<y<0.32, |z|<0.19 in head-bone frame, needs 30+ verts), the head bone's pivot on the Tobin rig, or the clearance rule (shifts only if clearance over 3.2 cm or under 0.8 cm; clamp -0.14..+0.10). Instrument it to find out.
5. **The Unity zips are not 1:1 with the web repo.** The web generator (`src/generators/unityPluginGenerator.ts`, v3.0.0) emits only: SetupWindow (about 560 generated lines vs 1,152 in the zip), Physics/Collider/WindZone, the shader, asmdefs, package.json, README, playbook, recipe, ExportedLook.json, texture metas/PNGs, `PresetGeometry.json` and the Blender addon. These strings exist nowhere in the web repo: `GenerateAndAttach`, `AetherStrandMeshGenerator`, `AetherStrandProceduralBuilder`, `Apply Active Hair Preset to Character`, `Run 3-Scenario Audit`, `Export AI Bundle`, `autoFitToHeadMesh`. So the Unity-side hair builder/attacher/diagnostics were added outside the web repo (probably by Neon), and a fresh web export would not contain Neon's fixes. Also the Unity 1-click REBUILDS hair in C# from PresetGeometry.json; it does not use the Blender FBX. So what the cloud session tested is the Unity-only route, NOT the combo.
6. **The Blender addon IS in the web app.** `generateBlenderAddonPy` (lines 2276-2943) emits `AetherStrand_Blender/aetherstrand_hair_cards.py`. Diffed against the zip's addon: 663 lines each, differing only in per-export substitutions (preset id `layered_swept_long`, part offset 0.032, FBX name) plus ONE real edit: `head_bone.tail = Vector((0,0,0.425))` in the web template vs `Vector((0,0,0.23))` in the zips. Effect of the shorter Head bone not tested. Extracted template (with `<<DYN>>` where `${...}` was): `scratch/web_template_addon_extracted.py`.
7. **Blender half on Tobin (headless Blender 4.5).** Operator `aetherstrand.generate_sculpted_hair` returns FINISHED: one mesh `AetherStrand_SculptedHairMesh` (25,192 verts, ARMATURE modifier), armature `AetherStrand_HairRig`, collection `AetherStrand_partedshag`. It takes NO head input: hair comes out at the preset's own origin, bounds x +-0.116, y -0.159..0.099, z -0.066..0.199 (relative to the head pivot). Tobin's AvatarHead is z 1.481..1.835 (world), 0.262 x 0.249 x 0.362. I seated it by hand, translating only the ROOT (armature) by +1.635 Z so crowns match. GOTCHA: the hair mesh is parented to the armature, so moving both doubles the shift (hair ended up at z 3.27, invisible); move only the parentless object. After seating (renders in `renders/blender_*`): fringe covers the eyes, bare scalp visible at the crown top and back, hair sides hang low over the ears. The addon never fits to a head, so a fit step is needed whichever route is chosen.
8. **Web side facts** (read, not run): hair is built on a fixed scalp ellipsoid, centre (0, 0.425, -0.01), half-axes 0.282 x 0.318 x 0.31 (`src/engine/hairBuilder.ts:44-47`), around a stylised bust whose head is 0.56 wide x 0.74 tall (aspect 1.32), head pivot (0, 0.44, 0) (`src/engine/bustModel.ts`). Physics: web `src/engine/hairPhysics.ts` is 5,326 lines; Unity `Runtime/AetherStrandPhysics.cs` is 741. Web shader `src/engine/hairShaders.ts` is 468 lines. None of these were compared for behaviour.

## Scratch project (how the cloud run was built; reuse it)
Make it outside the repo, e.g. `C:\Dev\scratch\aetherstrand-test`:
- `ProjectSettings/` copied from this repo; `Packages/manifest.json` and `packages-lock.json` copied from this repo's `Packages/`.
- The plugin's `AetherStrand_Unity` folder copied to `Packages/com.aetherstrand.sculptedhair/` (an embedded package, picked up automatically). Use v3.0.1.
- `Assets/Tobin/TobinBase.fbx` (from the v26 branch) and `Assets/Editor/HairTestRunner.cs` (saved here as `scratch/HairTestRunner.cs`; it drives the plugin through reflection so it needs no assembly reference).
- Run: `Tools\unity.ps1 exec -ProjectRoot <scratch> -OutDir <scratchpad> -Method HairTestRunner.Run` (Windows wrapper; the cloud used `bash Tools/cloud/unity.sh exec --project <scratch> --out <dir> --method HairTestRunner.Run --graphics`). Edit the `OutDir` constant at the top of the harness (it points at a cloud path). `ZeroOffset` is currently `true`; set it false to test the default 1-click path.
Harness gotchas learned: do NOT end with `EditorApplication.Exit(0)`; the wrapper only reports PASS if the log has "Exiting batchmode successfully", so a clean run looked like FAIL. Failures are signalled with `Debug.LogError`. `SkinnedMeshRenderer.bounds` for the body is the WHOLE body, so compute head bounds from vertices weighted over 0.5 to the Head bone (the harness does this).
